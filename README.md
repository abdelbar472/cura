# Cura

Modular clinical decision-support backend (FastAPI). A LangGraph orchestrator
runs five agents over one case, with an optional ML layer and Postgres-backed
case storage:

```
                    ┌──────────────────────────┐
  POST /v1/cases →  │  Orchestrator (LangGraph) │
                    └────────────┬─────────────┘
             ┌───────────┬───────┼─────────┬──────────────┐
             ▼           ▼       ▼         ▼              ▼
        ┌─────────┐ ┌───────┐ ┌───────┐ ┌─────────────┐ ┌────────┐
        │ Symptom │ │ Labs  │ │Imaging│ │Differential │ │ Drugs  │
        │ lexicon │ │ rules │ │ rules │ │   rules     │ │ curated│
        │ + MiniLM│ │ + IF  │ │ + ViT │ │ + LogReg    │ │ + alias│
        └────┬────┘ └───┬───┘ └───┬───┘ └──────┬──────┘ └───┬────┘
             └──────────┴─────────┴────────────┴────────────┘
                                   ▼
                        evidence codes → triage
                                   ▼
                 AgentEvents → bus (memory / Kafka)
                                   ▼
                 CaseResult + events → store (Postgres / memory)
```

> **Not a medical device.** Output is generated by deterministic rules, a small
> curated knowledge base, and optional models trained on synthetic or public
> data. It is not calibrated, not clinically validated, and must not be used for
> real clinical decisions. Do not send PHI to this service. Imaging output is a
> model flag, not a radiographic interpretation.

## Quickstart

```powershell
# from E:\codes\Cura
.\.venv\Scripts\Activate.ps1        # or: .\.venv\Scripts\python.exe ...
pip install -r requirements.txt

docker compose up -d                # Postgres 16 on localhost:5433
uvicorn app.main:app --reload       # or: python main.py
```

- OpenAPI docs: <http://127.0.0.1:8000/docs>
- Health: <http://127.0.0.1:8000/healthz> (includes store and model states)

The first ML request may download model weights (MiniLM for embeddings, a ViT
checkpoint for chest X-rays) and train/cache the sklearn models under
`artifacts/`. Set `CURA_ML_ENABLED=false`, or `CURA_STORE_BACKEND=memory`, to run
with no model downloads and no database.

### Example case

```bash
curl -X POST http://127.0.0.1:8000/v1/cases \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Dysuria, urinary frequency and fever for two days. Denies chest pain.",
    "patient": {"age_years": 34, "sex": "female"},
    "labs": [
      {"name": "WBC", "value": 15.2, "unit": "10^9/L"},
      {"name": "CRP", "value": 48.0, "unit": "mg/L"}
    ],
    "medications": [{"name": "Ibuprofen 400 mg"}, {"name": "Coumadin 5 mg"}],
    "client_reference": "ED-1001"
  }'
```

Response (abridged):

```json
{
  "case_id": "case_…",
  "status": "ok",
  "triage": {"level": "urgent", "action": "Seek same-day clinical assessment…"},
  "symptom": {"evidence_codes": ["E_DYSURIA", "E_FREQUENCY", "E_FEVER"]},
  "labs": {"evidence_codes": ["E_LEUKOCYTOSIS", "E_CRP_ELEVATED"]},
  "imaging": null,
  "differential": {
    "considerations": [
      {"condition_id": "COND_UTI", "score": 0.99, "acuity": "routine"}
    ]
  },
  "drug_safety": {"overall_risk": "major"},
  "disclaimer": "Cura is a research prototype…"
}
```

### Imaging request

Only chest X-rays are interpreted, and only when image bytes are supplied:

```json
{
  "modality": "xray",
  "body_site": "chest",
  "clinical_question": "Infiltration?",
  "image_base64": "<base64 or data:image/...;base64,...>"
}
```

Other modalities return `status: "unavailable"` with no findings. Invalid image
bytes return `status: "error"` rather than fabricated output.

## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/` | Service metadata |
| GET | `/healthz` | Liveness, bus/store backends, model readiness |
| GET | `/v1/agents` | Agent registry |
| GET | `/v1/knowledge/conditions` | Condition knowledge base |
| POST | `/v1/cases` | Run the full pipeline (201) |

| GET | `/v1/cases/{case_id}/events` | Per-agent events |
| POST | `/v1/agents/symptom` | Run the symptom agent alone |
| POST | `/v1/agents/labs` | Run the lab agent alone |
| POST | `/v1/agents/differential` | Run the differential agent alone |
| POST | `/v1/agents/drugs` | Run the drug-safety agent alone |
| POST | `/v1/agents/imaging` | Run the imaging agent alone |

Run IDs, case IDs, and step IDs are optional on every direct agent request and
generated when omitted.

## Agents

| Agent | Implementation | Model version |
| --- | --- | --- |
| symptom | Curated lexicon + regex, optional scispaCy union, optional MiniLM semantic recall; negation heuristics | `symptom-ner@0.2.0+symptom-lexicon@0.2.0` |
| labs | Reference ranges, unit checking, critical thresholds; optional IsolationForest panel score | `lab-rules@0.2.0+lab-references@2026.1` |
| imaging | Chest X-ray ViT classifier when an image is supplied; null backend otherwise | `imaging@0.2.0` |
| differential | Weighted log-odds over 13 conditions, age/sex modifiers; optional logistic re-ranker | `differential-weighted@0.2.0+condition-kb@0.2.0` |
| drugs | Curated interaction table + duplicate-therapy classes; hybrid name resolver | `drug-safety@0.2.0+interaction-kb@2026.1` |
| orchestrator | LangGraph `StateGraph` (falls back to sequential if unavailable) | `orchestrator@0.2.0` |

Every agent returns the same envelope: `run_id`, `case_id`, `step_id`,
`status` (`ok | partial | unavailable | error`), `model_version`,
`input_hash`, `warnings`, `errors`, and an optional `ml` usage record
(`name`, `version`, `framework`, `ready`, `fallback`, `detail`).

### ML layer

Models are constructed once in `app/ml/bundle.py`, loaded lazily on first use,
and never loaded at import or application startup. Deterministic rules remain
authoritative; a model can add recall or re-rank but cannot silently replace a
rule result.

| Agent | Model | Role | Fallback |
| --- | --- | --- | --- |
| symptom | `all-MiniLM-L6-v2` sentence embeddings | Adds symptom codes for lay paraphrases the lexicon misses; lexicon/scispaCy matches win on overlap | Lexicon only; warning recorded |
| labs | scikit-learn `IsolationForest` | Panel-level anomaly score over 18 reference-range z-scores + masks | Per-value rule flags unchanged |
| differential | multinomial `LogisticRegression` | Blended re-ranking (65% rules / 35% model by default) over curated evidence | Weighted log-odds only |
| drugs | alias/fuzzy + MiniLM embeddings | Resolves typos, salts/forms, and brand variants; approximate matches add warnings | Exact/alias/curated table only |
| imaging | HF ViT chest X-ray classifier | Flags a pneumonia pattern above a confidence threshold | `unavailable`, no findings |

The sklearn models train on seeded synthetic data derived from the curated
knowledge base and cache to `artifacts/` (`lab_anomaly.joblib`,
`differential_logreg.joblib`). They are reproducible but their scores are
heuristic, not calibrated probabilities. The imaging checkpoint is a single
public NORMAL-vs-PNEUMONIA model, not a validated radiology system.

If a model is disabled or fails to load, the agent returns its rule-based output
with `ml.fallback = true` and a `detail` explaining the fallback. `/healthz`
reports `ml_enabled` plus each model's `enabled` and `ready` state.

### Evidence codes

Agents communicate through versioned evidence codes instead of free text, e.g.

- symptoms: `E_DYSURIA`, `E_FREQUENCY`, `E_CHEST_PAIN`, `E_SOB`
- labs: `E_LEUKOCYTOSIS`, `E_CRP_ELEVATED`, `E_LACTATE_CRITICAL`, `E_AKI`
- imaging: `E_PNEUMONIA` (model flag only, chest X-ray)

The orchestrator unions all codes and passes them to the differential agent.
Triage (`routine | urgent | emergency`) is computed from red flags, critical
lab values, interaction severity, and the leading consideration's acuity.

## Case store

Default backend is Postgres. `docker-compose.yml` starts Postgres 16 on host
port **5433** (local 5432 is intentionally not used):

```powershell
docker compose up -d
# CURA_DATABASE_URL=postgresql+psycopg://cura:cura@localhost:5433/cura
```

On connect, the store creates the `cases` and `case_events` tables with
SQLAlchemy `create_all` (no Alembic migrations in this prototype). Case results
and event payloads are stored as JSON so the Pydantic response models remain the
source of truth. Re-saving a case replaces its event rows.

If Postgres is unreachable, startup logs a warning and falls back to the bounded
in-memory store with `degraded = true`; `/healthz` reports `store` and
`store_degraded`. Use `CURA_STORE_BACKEND=memory` to skip the database entirely.

The store's public API is async, but SQLAlchemy's synchronous engine runs in
worker threads. That keeps it portable across event-loop policies, including
Windows' default Proactor loop (which psycopg's async driver cannot use).

## Configuration

Settings use the `CURA_` prefix. See `.env.example` for the full list.

| Variable | Default | Notes |
| --- | --- | --- |
| `CURA_ENVIRONMENT` | `dev` | `dev`, `test`, `prod` |
| `CURA_STORE_BACKEND` | `postgres` | `postgres` or `memory` |
| `CURA_STORE_MAX_CASES` | `1000` | In-memory LRU capacity |
| `CURA_DATABASE_URL` | `postgresql+psycopg://cura:cura@localhost:5433/cura` | Async SQLAlchemy URL |
| `CURA_DATABASE_ECHO` | `false` | Log SQL statements |
| `CURA_ML_ENABLED` | `true` | Master switch for the lazy ML layer |
| `CURA_ML_DEVICE` | `cpu` | `cpu` or a CUDA device string |
| `CURA_ML_ARTIFACT_DIR` | `artifacts` | sklearn/joblib cache directory |
| `CURA_EMBEDDING_MODEL` | `sentence-transformers/all-MiniLM-L6-v2` | Embeddings for symptom/drug matching |
| `CURA_SYMPTOM_ML_THRESHOLD` | `0.55` | Minimum semantic similarity |
| `CURA_SYMPTOM_ML_MARGIN` | `0.05` | Best-vs-runner-up margin |
| `CURA_LAB_ANOMALY_CONTAMINATION` | `0.10` | IsolationForest contamination |
| `CURA_DIFFERENTIAL_ML_WEIGHT` | `0.35` | Model weight in the blend |
| `CURA_DRUG_FUZZY_THRESHOLD` | `0.84` | Minimum string-similarity score |
| `CURA_DRUG_EMBEDDING_THRESHOLD` | `0.72` | Minimum embedding similarity |
| `CURA_SYMPTOM_BACKEND` | `auto` | `auto`, `lexicon`, `scispacy` |
| `CURA_DIFFERENTIAL_TOP_K` | `5` | Max considerations returned |
| `CURA_DIFFERENTIAL_MIN_SCORE` | `0.05` | Score cutoff |
| `CURA_IMAGING_BACKEND` | `auto` | `auto`, `null`, `hf` |
| `CURA_IMAGING_MODEL_ID` | `nickmuchi/vit-finetuned-chest-xray-pneumonia` | HF checkpoint |
| `CURA_IMAGING_CONFIDENCE_THRESHOLD` | `0.55` | Pneumonia flag threshold |
| `CURA_KAFKA_ENABLED` | `false` | Falls back to memory bus if the broker is down |
| `CURA_KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092` | Broker list |

## Testing

```powershell
.\.venv\Scripts\python.exe -m pytest
```

72 tests cover the lexicon/negation path, lab flags and panel anomalies,
differential ranking and blending, drug normalisation/resolution/interactions,
the imaging null and HF paths, the full case pipeline, event publishing, request
validation, async case-store eviction/copy semantics, and the Postgres backend.

The Postgres integration tests are skipped unless a test database is provided:

```powershell
docker compose up -d
$env:CURA_TEST_DATABASE_URL='postgresql+psycopg://cura:cura@localhost:5433/cura'
.\.venv\Scripts\python.exe -m pytest
```

Tests inject fake embedding/imaging/agent models, so they never download model
weights. The sklearn models are trained into temporary artifact directories.

## Optional scispaCy

```powershell
pip install spacy
pip install https://s3-us-west-2.amazonaws.com/ai2-s2-scispacy/releases/v0.5.4/en_core_sci_sm-0.5.4.tar.gz
```

If the model is missing, the symptom agent logs a warning once and uses the
lexicon, so the API never depends on a model download. Lexicon matches are
always unioned in, so enabling scispaCy cannot reduce symptom recall.

## Optional Kafka

Set `CURA_KAFKA_ENABLED=true`. Each step publishes
`<prefix>.<agent>.result` with the full result payload, keyed by `case_id`.
Events are also retained in the case store, which powers
`GET /v1/cases/{id}/events` regardless of bus backend.

## Layout

```
app/
  main.py                  app factory, lifespan, Windows loop setup
  config.py                pydantic-settings
  api/                     routes + dependencies
  schemas/                 shared envelope, triage, case models
  agents/
    symptom/               lexicon/scispaCy NER + semantic union → mapper
    labs/                  reference-range interpreter + anomaly integration
    differential/          weighted evidence ranking + re-ranker blend
    drugs/                 normaliser + resolver + interaction review
    imaging/               model protocol + null/HF backends
    orchestrator/          LangGraph state, nodes, triage
    registry.py            agent catalogue + failure results
  knowledge/               symptoms, labs, conditions, interactions (data)
  ml/                      embeddings, semantic matcher, anomaly/LogReg models,
                           drug resolver, HF imaging, model bundle
  bus/                     memory + Kafka event transports
  store/                   async store contract, memory + Postgres backends
tests/
```

## Limitations / roadmap

- Models are prototypes: synthetic training data, no external validation, no
  calibration, and no prospective clinical evaluation.
- Imaging is chest X-ray only and returns a model flag, not a report. DICOM,
  multipart upload, and other modalities are not implemented.
- No authentication, authorization, audit log, or PHI handling. Do not use with
  real patient data.
- Postgres schema creation uses `create_all`; production should add migrations,
  retention, and encryption.
- Differential scores and anomaly scores are heuristic, not probabilities of
  disease.
- Kafka is wired but not integration-tested with a broker.
