# Cura

Modular clinical decision-support backend (FastAPI). A LangGraph orchestrator
runs five agents over one case:

```
                    ┌──────────────────────────┐
  POST /v1/cases →  │  Orchestrator (LangGraph) │
                    └────────────┬─────────────┘
             ┌───────────┬───────┼─────────┬──────────────┐
             ▼           ▼       ▼         ▼              ▼
        ┌─────────┐ ┌───────┐ ┌───────┐ ┌─────────────┐ ┌────────┐
        │ Symptom │ │ Labs  │ │Imaging│ │Differential │ │ Drugs  │
        │  (NLP)  │ │(ranges│ │(null  │ │ (weighted   │ │(curated│
        │         │ │ rules)│ │backend│ │  evidence)  │ │ table) │
        └────┬────┘ └───┬───┘ └───┬───┘ └──────┬──────┘ └───┬────┘
             └──────────┴─────────┴────────────┴────────────┘
                                   ▼
                        evidence codes → triage
                                   ▼
                   AgentEvents → event bus (memory / Kafka)
```

> **Not a medical device.** Output is generated by deterministic rules and a
> small curated knowledge base. It is not calibrated, not validated, and must
> not be used for real clinical decisions. Do not send PHI to this service.

## Quickstart

```powershell
# from E:\codes\Cura
.\.venv\Scripts\Activate.ps1        # or: .\.venv\Scripts\python.exe ...
pip install -r requirements.txt
uvicorn app.main:app --reload       # or: python main.py
```

- OpenAPI docs: <http://127.0.0.1:8000/docs>
- Health: <http://127.0.0.1:8000/healthz>

The local `.venv` already contains every dependency, so `uvicorn app.main:app
--reload` works immediately.

### Example case

```bash
curl -X POST http://127.0.0.1:8000/v1/cases \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Dysuria, urinary frequency and fever for two days. Denies chest pain.",
    "patient": {"age_years": 34, "sex": "female"},
    "labs": [
      {"name": "WBC", "value": 15.2, "unit": "10^9/L"},
      {"name": "CRP", "value": 48.0, "unit": "mg/L"}
    ],
    "medications": [{"name": "Ibuprofen 400 mg"}, {"name": "Coumadin 5 mg"}],
    "client_reference": "ED-1001"
  }'
```

Response (abridged):

```json
{
  "case_id": "case_…",
  "status": "ok",
  "triage": {"level": "urgent", "action": "Seek same-day clinical assessment…"},
  "symptom": {"evidence_codes": ["E_DYSURIA", "E_FREQUENCY", "E_FEVER"]},
  "labs": {"evidence_codes": ["E_LEUKOCYTOSIS", "E_CRP_ELEVATED"]},
  "imaging": null,
  "differential": {
    "considerations": [
      {"condition_id": "COND_UTI", "score": 0.99, "acuity": "routine"}
    ]
  },
  "drug_safety": {"overall_risk": "major"},
  "disclaimer": "Cura is a research prototype…"
}
```

## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/` | Service metadata |
| GET | `/healthz` | Liveness, bus backend, agent status |
| GET | `/v1/agents` | Agent registry |
| GET | `/v1/knowledge/conditions` | Condition knowledge base |
| POST | `/v1/cases` | Run the full pipeline (201) |
| GET | `/v1/cases?limit=20` | Recent case summaries |
| GET | `/v1/cases/{case_id}` | Stored case result |
| GET | `/v1/cases/{case_id}/events` | Per-agent events |
| POST | `/v1/agents/symptom` | Run the symptom agent alone |
| POST | `/v1/agents/labs` | Run the lab agent alone |
| POST | `/v1/agents/differential` | Run the differential agent alone |
| POST | `/v1/agents/drugs` | Run the drug-safety agent alone |
| POST | `/v1/agents/imaging` | Run the imaging agent alone |

Run IDs, case IDs, and step IDs are optional on every direct agent request and
generated when omitted.

## Agents

| Agent | Implementation | Model version |
| --- | --- | --- |
| symptom | Curated lexicon + regex, with optional scispaCy (`en_core_sci_sm`) union; negation heuristics | `symptom-ner@0.2.0+symptom-lexicon@0.2.0` |
| labs | Reference ranges, unit checking, critical thresholds | `lab-rules@0.2.0+lab-references@2026.1` |
| imaging | Request validation only; pluggable model protocol, null backend | `imaging@0.1.0` |
| differential | Weighted log-odds over 13 conditions, age/sex modifiers | `differential-weighted@0.2.0+condition-kb@0.2.0` |
| drugs | Curated interaction table + duplicate-therapy classes | `drug-safety@0.2.0+interaction-kb@2026.1` |
| orchestrator | LangGraph `StateGraph` (falls back to sequential if unavailable) | `orchestrator@0.2.0` |

Every agent returns the same envelope: `run_id`, `case_id`, `step_id`,
`status` (`ok | partial | unavailable | error`), `model_version`,
`input_hash`, `warnings`, `errors`.

### Evidence codes

Agents communicate through versioned evidence codes instead of free text, e.g.

- symptoms: `E_DYSURIA`, `E_FREQUENCY`, `E_CHEST_PAIN`, `E_SOB`
- labs: `E_LEUKOCYTOSIS`, `E_CRP_ELEVATED`, `E_LACTATE_CRITICAL`, `E_AKI`
- imaging: none implemented yet

The orchestrator unions all codes and passes them to the differential agent.
Triage (`routine | urgent | emergency`) is computed from red flags, critical
lab values, interaction severity, and the leading consideration's acuity.

## Configuration

Settings use the `CURA_` prefix. See `.env.example`.

| Variable | Default | Notes |
| --- | --- | --- |
| `CURA_ENVIRONMENT` | `dev` | `dev`, `test`, `prod` |
| `CURA_STORE_MAX_CASES` | `1000` | In-memory LRU capacity |
| `CURA_SYMPTOM_BACKEND` | `auto` | `auto`, `lexicon`, `scispacy` |
| `CURA_DIFFERENTIAL_TOP_K` | `5` | Max considerations returned |
| `CURA_DIFFERENTIAL_MIN_SCORE` | `0.05` | Score cutoff |
| `CURA_KAFKA_ENABLED` | `false` | Falls back to memory bus if the broker is down |
| `CURA_KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092` | Broker list |

## Testing

```powershell
.\.venv\Scripts\python.exe -m pytest
```

30 tests cover the lexicon/negation path, lab flags, differential ranking,
drug normalisation and interactions, the imaging placeholder, the full case
pipeline, event publishing, and request validation.

## Optional scispaCy

```powershell
pip install spacy
pip install https://s3-us-west-2.amazonaws.com/ai2-s2-scispacy/releases/v0.5.4/en_core_sci_sm-0.5.4.tar.gz
```

If the model is missing, the symptom agent logs a warning once and uses the
lexicon, so the API never depends on a model download. Lexicon matches are
always unioned in, so enabling scispaCy cannot reduce symptom recall.

## Optional Kafka

Set `CURA_KAFKA_ENABLED=true`. Each step publishes
`<prefix>.<agent>.result` with the full result payload, keyed by `case_id`.
Events are also retained in the case store, which powers
`GET /v1/cases/{id}/events` regardless of bus backend.

## Layout

```
app/
  main.py                  app factory, lifespan, error handler
  config.py                pydantic-settings
  api/                     routes + dependencies
  schemas/                 shared envelope, triage, case models
  agents/
    symptom/               model.py (NER) → mapper.py → agent.py
    labs/                  reference-range interpreter
    differential/          weighted evidence ranking
    drugs/                 normaliser + interaction review
    imaging/               model protocol + null backend
    orchestrator/          LangGraph state, nodes, triage
    registry.py            agent catalogue + failure results
  knowledge/               symptoms, labs, conditions, interactions (data)
  bus/                     memory + Kafka event transports
  store/                   bounded in-memory case store
tests/
```

## Limitations / roadmap

- No persistence: cases and events live in process memory.
- No authentication, authorization, audit log, or PHI handling.
- No imaging model; the agent intentionally reports `unavailable` rather than
  fabricating findings. X-ray first, then CTA.
- Differential scores are heuristic log-odds, not calibrated probabilities.
- No real ML models yet; each agent has a stable interface where one can be
  dropped in (`run_*` function + `model_version`).
- Kafka is wired but not integration-tested with a broker.
- Multipart image upload and DICOM handling are not implemented.
